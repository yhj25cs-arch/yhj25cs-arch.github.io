## 1. ERC-20 등장 배경 및 목적

ERC-20은 2015년 Fabian Vogelsteller와 Vitalik Buterin이 제안한 이더리움의 토큰 표준이다.

이더리움에서는 스마트 컨트랙트를 이용하여 다양한 토큰을 발행할 수 있다. 하지만 토큰마다 전송 방식이나 잔액 조회 방식이 다르다면 지갑이나 거래소에서 각각의 토큰에 맞는 기능을 구현해야 하는 문제가 발생한다.

ERC-20은 이러한 문제를 해결하기 위해 토큰이 공통적으로 제공해야 하는 함수와 이벤트를 표준화하였다.

## 2. ERC-20의 핵심 구조

ERC-20은 대체 가능한 토큰(Fungible Token)을 관리하기 위한 표준이다. 같은 종류의 토큰이라면 개별 토큰을 구분하지 않고 수량을 기준으로 관리한다.

### 2.1. 주요 함수

| 함수 | 역할 |
| --- | --- |
| totalSupply() | 전체 토큰 발행량 조회 |
| balanceOf() | 특정 주소의 토큰 잔액 조회 |
| transfer() | 자신의 토큰 전송 |
| approve() | 다른 주소에 토큰 사용 권한 부여 |
| transferFrom() | 위임받은 권한으로 토큰 전송 |
| allowance() | 남아 있는 토큰 사용 승인량 조회 |

토큰 이름, 기호, 소수점 단위를 조회하는 name(), symbol(), decimals()는 선택적으로 구현할 수 있다.

### 2.2. 데이터 관리 구조

ERC-20의 잔액과 사용 승인량은 일반적으로 다음과 같은 mapping을 이용하여 관리한다.

```solidity
mapping(address => uint256) private balances;

mapping(address => mapping(address => uint256))
    private allowances;
```

balances는 주소별 토큰 잔액을 저장하며 allowances는 토큰 소유자가 특정 주소에 허용한 사용량을 저장한다.

## 3. 토큰 전송 및 사용 승인 방식

### 3.1. transfer()

```solidity
function transfer(address to, uint256 amount)
    external returns (bool);
```

함수를 호출한 사용자의 토큰을 to 주소로 amount만큼 전송한다.

100개의 토큰을 가진 A가 B에게 30개를 전송한다면 A의 잔액은 70개가 되고 B의 잔액은 30개 증가한다.

### 3.2. approve()와 transferFrom()

```solidity
function approve(address spender, uint256 amount)
    external returns (bool);

function transferFrom(
    address from,
    address to,
    uint256 amount
) external returns (bool);
```

approve()는 토큰을 직접 전송하는 함수가 아니라 다른 주소가 일정량의 토큰을 사용할 수 있도록 권한을 부여하는 함수이다.

사용자 A가 스마트 컨트랙트 C에 100개의 토큰 사용을 승인했다고 가정해 보자.

```text
A의 토큰 잔액: 500
C에 부여한 승인량: 100

C가 transferFrom()으로 30개 전송

A의 토큰 잔액: 470
남은 승인량: 70
```

스마트 컨트랙트 C는 승인받은 범위 내에서 A의 토큰을 전송할 수 있다.

이러한 구조는 사용자가 자신의 토큰을 직접 전송하지 않더라도 DeFi 서비스에서 토큰 교환이나 예치 등의 기능을 수행할 수 있도록 한다.

## 4. 실제 활용 사례

### 4.1. USDC

USDC는 미국 달러의 가치에 연동되도록 설계된 스테이블코인이다. 이더리움에서는 ERC-20 표준을 기반으로 전송 및 잔액 조회 등의 기능을 제공한다.

- [Etherscan - USDC 컨트랙트](https://etherscan.io/token/0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48)

USDC는 소수점 단위로 6을 사용한다. 따라서 컨트랙트 내부에서 1 USDC는 1,000,000이라는 정수로 표현된다.

### 4.2. DeFi 서비스

탈중앙화 거래소에서 ERC-20 토큰을 교환할 때는 거래에 사용되는 컨트랙트나 승인 관리 컨트랙트에 토큰 사용 권한을 부여하는 과정이 필요할 수 있다.

승인된 컨트랙트는 transferFrom()을 이용하여 사용자의 토큰을 이동할 수 있다.

이러한 공통 인터페이스 덕분에 서로 다른 종류의 ERC-20 토큰을 동일한 서비스에서 처리할 수 있다.

## 5. 보안상 고려할 점

### 5.1. 과도한 토큰 사용 승인

사용자가 컨트랙트에 필요한 양보다 많은 토큰 사용 권한을 부여하면 해당 컨트랙트가 침해되었을 때 피해 범위가 커질 수 있다.

```solidity
token.approve(spender, type(uint256).max);
```

위 코드는 매우 큰 승인량을 설정하여 사실상 무제한 사용을 허용하는 예시이다.

사용자가 매번 승인하지 않아도 된다는 편리함이 있지만 보안 측면에서는 불필요한 승인 권한을 제거하고 필요한 수량만 승인하는 것이 안전하다.

### 5.2. 승인량 변경 문제

approve()는 기존 승인량에 값을 더하는 것이 아니라 새로운 값으로 덮어쓰는 방식이다.

승인량을 변경하는 과정에서 트랜잭션의 처리 순서에 따라 기존 승인량과 새 승인량이 모두 사용될 가능성이 있다.

ERC-20 공식 문서에서는 이러한 문제를 줄이기 위해 기존 승인량을 0으로 설정한 이후 새로운 승인량을 설정하는 방식을 권고하고 있다.

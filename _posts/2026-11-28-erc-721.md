## 1. ERC-721 등장 배경 및 목적

ERC-721은 2018년에 제안된 대체 불가능한 토큰(NFT)의 표준이다.

ERC-20은 토큰을 수량으로 관리하기 때문에 각각의 토큰이 서로 다른 특성이나 가치를 가진 자산을 표현하기 어렵다.

ERC-721은 개별 토큰에 고유한 식별자를 부여하고 각각의 소유권을 관리할 수 있도록 만들어졌다.

## 2. ERC-721의 핵심 구조

### 2.1. Token ID

ERC-721에서는 각각의 NFT를 tokenId를 이용하여 구분한다.

동일한 컨트랙트에서 발행된 NFT라도 tokenId가 다르면 서로 다른 자산이다.

```solidity
mapping(uint256 => address) private owners;
mapping(address => uint256) private balances;
```

owners는 각 NFT의 소유자 주소를 저장하며 balances는 각 주소가 보유한 NFT의 개수를 저장한다.

특정 이더리움 체인에서는 컨트랙트 주소와 tokenId의 조합으로 NFT를 식별할 수 있다.

### 2.2. 주요 함수

| 함수 | 역할 |
| --- | --- |
| balanceOf() | 사용자가 보유한 NFT 개수 조회 |
| ownerOf() | 특정 NFT의 소유자 조회 |
| transferFrom() | NFT 소유권 이전 |
| safeTransferFrom() | 수신 컨트랙트의 NFT 수신 기능을 확인하며 전송 |
| approve() | 특정 NFT의 사용 권한 부여 |
| setApprovalForAll() | 해당 컨트랙트 내 모든 보유 NFT의 관리 권한 부여 |
| getApproved() | 특정 NFT의 승인 주소 조회 |
| isApprovedForAll() | 전체 관리 권한 승인 여부 조회 |

## 3. NFT의 소유권 이전 방식

ERC-20은 전송할 토큰의 수량을 지정하지만 ERC-721은 전송할 NFT의 tokenId를 지정한다.

```solidity
function transferFrom(
    address from,
    address to,
    uint256 tokenId
) external;
```

예를 들어 사용자 A가 tokenId가 1인 NFT를 사용자 B에게 전송한다면 해당 NFT의 소유자가 A에서 B로 변경된다.

정상적인 소유권 이전을 위해서는 함수를 호출한 사용자가 NFT의 소유자이거나 승인받은 주소인지 확인해야 한다.

### 3.1. safeTransferFrom()

```solidity
function safeTransferFrom(
    address from,
    address to,
    uint256 tokenId
) external;
```

NFT를 스마트 컨트랙트 주소로 전송하는 경우 해당 컨트랙트가 NFT를 받을 수 있는지 확인할 필요가 있다.

safeTransferFrom()은 수신 주소가 스마트 컨트랙트일 경우 onERC721Received()를 호출하고 요구되는 반환값을 확인한다.

정상적인 반환값이 전달되지 않으면 트랜잭션이 실패한다.

이를 통해 NFT를 처리할 수 없는 컨트랙트에 토큰이 전송되는 문제를 줄일 수 있다.

## 4. NFT와 메타데이터

ERC-721의 선택적 메타데이터 확장에서는 tokenURI()를 이용하여 특정 NFT와 연결된 URI를 조회할 수 있다.

```solidity
function tokenURI(uint256 tokenId)
    external view returns (string memory);
```

URI가 가리키는 JSON 데이터는 다음과 같은 형태로 구성될 수 있다.

```json
{
    "name": "Example NFT",
    "description": "NFT metadata example",
    "image": "ipfs://example"
}
```

NFT의 이미지 자체가 반드시 블록체인에 저장되는 것은 아니다. 블록체인에는 소유권 정보와 메타데이터를 참조할 수 있는 URI가 저장될 수 있다.

## 5. 실제 활용 사례

### 5.1. Bored Ape Yacht Club(BAYC)

BAYC는 ERC-721 표준을 기반으로 발행된 NFT 컬렉션이다.

각 NFT는 서로 다른 tokenId를 가지고 있으며 ownerOf()를 통해 특정 NFT의 소유자를 조회할 수 있다.

- [Etherscan - BAYC 컨트랙트](https://etherscan.io/token/0xbc4ca0eda7647a8ab7c2061c2e118a18a936f13d)

### 5.2. 기존 NFT 발행 실습과의 연관성

이전에 블록체인 응용 수업에서 Sepolia 테스트넷을 이용하여 NFT를 직접 발행한 경험이 있다.

당시 NFT를 발행한 이후 컨트랙트 주소, 트랜잭션 정보, Token ID와 메타데이터 URI를 확인하였다.

이번 학습을 통해 이러한 정보가 각각 NFT의 식별, 소유권 관리, 메타데이터 연결과 관련되어 있다는 점을 이해할 수 있었다.

## 6. 보안상 고려할 점

### 6.1. 전체 NFT 관리 권한 승인

```solidity
function setApprovalForAll(
    address operator,
    bool approved
) external;
```

approve()는 특정 NFT에 대한 권한을 부여하는 반면 setApprovalForAll()은 해당 컨트랙트에서 사용자가 보유한 모든 NFT에 대한 관리 권한을 부여한다.

따라서 신뢰할 수 없는 주소에 전체 관리 권한을 승인할 경우 여러 NFT가 동시에 유출될 가능성이 있다.

### 6.2. 메타데이터의 영속성

NFT의 메타데이터나 이미지가 외부 서버에 저장되어 있다면 서버가 종료되거나 파일이 삭제되면서 해당 정보에 접근할 수 없게 될 수 있다.

블록체인에 기록된 NFT의 소유권이 유지된다고 해서 연결된 이미지와 메타데이터까지 영구적으로 유지되는 것은 아니다.

따라서 NFT를 설계할 때에는 외부 데이터의 저장 방식과 변경 가능성도 함께 고려해야 한다.

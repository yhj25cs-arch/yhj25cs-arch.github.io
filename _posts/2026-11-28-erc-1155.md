## 1. ERC-1155 등장 배경 및 목적

ERC-1155는 2018년에 제안된 멀티 토큰 표준(Multi Token Standard)이다.

블록체인 게임에는 게임 내 화폐, 소비형 아이템, 고유한 장비 등 다양한 형태의 자산이 존재할 수 있다.

ERC-20을 이용하여 여러 종류의 대체 가능한 토큰을 관리하려면 일반적으로 각각의 토큰 컨트랙트가 필요하다. ERC-721은 하나의 컨트랙트에서 여러 NFT를 관리할 수 있지만 동일한 종류의 아이템을 수량으로 관리하는 용도로는 적합하지 않다.

ERC-1155는 하나의 스마트 컨트랙트에서 다양한 종류의 토큰을 관리할 수 있도록 이러한 한계를 개선한 표준이다.

## 2. ERC-1155의 핵심 구조

### 2.1. 토큰 종류와 수량 관리

ERC-1155는 tokenId를 통해 토큰의 종류를 구분하고 각 주소가 보유한 해당 토큰의 수량을 관리한다.

```solidity
mapping(uint256 => mapping(address => uint256))
    private balances;
```

블록체인 게임의 아이템을 관리한다고 가정해 보자.

| Token ID | 자산 종류 | 사용자 A의 보유량 |
| --- | --- | --- |
| 1 | 게임 내 화폐 | 1,000 |
| 2 | 회복 물약 | 20 |
| 3 | 고유한 장비 | 1 |

하나의 컨트랙트에서 화폐와 아이템 그리고 고유한 장비를 함께 관리할 수 있다.

다만 특정 토큰을 NFT로 사용하려면 발행량 제한 등의 규칙을 컨트랙트에서 별도로 구현해야 한다.

### 2.2. 주요 함수

| 함수 | 역할 |
| --- | --- |
| balanceOf() | 특정 토큰의 보유량 조회 |
| balanceOfBatch() | 여러 토큰의 보유량 조회 |
| safeTransferFrom() | 한 종류의 토큰 전송 |
| safeBatchTransferFrom() | 여러 종류의 토큰 일괄 전송 |
| setApprovalForAll() | 토큰 관리 권한 부여 |
| isApprovedForAll() | 관리 권한 승인 여부 조회 |

## 3. Batch Transfer 동작 원리

ERC-1155의 대표적인 특징은 여러 종류의 토큰을 하나의 함수 호출로 전송할 수 있다는 점이다.

### 3.1. 단일 토큰 전송

```solidity
function safeTransferFrom(
    address from,
    address to,
    uint256 id,
    uint256 amount,
    bytes calldata data
) external;
```

id는 전송할 토큰의 종류를 나타내며 amount는 전송할 수량을 나타낸다.

ERC-721에서는 특정 tokenId의 소유권을 이전하지만 ERC-1155에서는 특정 tokenId에 해당하는 토큰을 지정된 수량만큼 전송한다.

### 3.2. 여러 토큰 일괄 전송

```solidity
function safeBatchTransferFrom(
    address from,
    address to,
    uint256[] calldata ids,
    uint256[] calldata amounts,
    bytes calldata data
) external;
```

기존 단일 전송 함수와 달리 토큰의 식별자와 수량을 배열로 전달한다.

```text
ids     = [1, 2, 3]
amounts = [100, 5, 1]
```

위 데이터를 전달하면 다음과 같은 토큰 전송을 하나의 함수 호출로 처리할 수 있다.

| Token ID | 전송 수량 |
| --- | --- |
| 1 | 100 |
| 2 | 5 |
| 3 | 1 |

컨트랙트는 각 배열의 동일한 인덱스에 위치한 tokenId와 수량을 대응시켜 처리한다.

여러 토큰을 각각 전송하기 위한 트랜잭션을 생성하는 대신 하나의 트랜잭션으로 처리할 수 있으므로 가스비를 절감할 수 있다.

다만 실제 가스비 절감량은 컨트랙트의 구현 방식과 처리하는 토큰 수에 따라 달라진다.

## 4. ERC-20, ERC-721, ERC-1155 비교

| 구분 | ERC-20 | ERC-721 | ERC-1155 |
| --- | --- | --- | --- |
| 관리 대상 | 대체 가능한 토큰 | NFT | 다양한 유형의 토큰 |
| 관리 기준 | 수량 | Token ID | Token ID와 수량 |
| 개별 토큰의 고유성 | 없음 | 있음 | 구현에 따라 달라짐 |
| 표준 일괄 전송 함수 | 없음 | 없음 | 있음 |
| 주요 활용 | 화폐, DeFi | NFT | 게임 아이템, NFT |

ERC-1155는 ERC-20과 ERC-721의 활용 범위를 하나의 컨트랙트에서 다룰 수 있도록 설계되었지만 기존 두 표준과 동일한 인터페이스를 제공하는 것은 아니다.

## 5. 실제 활용 사례

ERC-1155는 다양한 종류의 자산을 함께 관리해야 하는 블록체인 게임이나 NFT 마켓플레이스에서 활용된다.

대표적인 활용 분야 중 하나는 Enjin의 블록체인 게임 아이템 관리 방식이다. 여러 종류의 게임 아이템을 각각 다른 컨트랙트로 관리하는 대신 Token ID를 기준으로 구분할 수 있다.

NFT 마켓플레이스에서도 동일한 종류의 디지털 콘텐츠를 여러 개 발행하거나 여러 자산을 관리할 때 ERC-1155를 활용할 수 있다.

## 6. 보안상 고려할 점

### 6.1. 일괄 전송 시 입력 검증

safeBatchTransferFrom()은 여러 개의 토큰 ID와 수량을 배열로 전달받는다.

따라서 구현 과정에서 두 배열의 길이가 일치하는지, 각 토큰의 잔액이 충분한지, 요청자가 토큰을 전송할 권한을 가지고 있는지 확인해야 한다.

```solidity
require(ids.length == amounts.length,
        "Array length mismatch");
```

위 코드는 토큰 ID 배열과 수량 배열의 길이를 확인하는 간단한 예시이다.

### 6.2. 외부 컨트랙트 호출과 재진입 위험

ERC-1155는 스마트 컨트랙트로 토큰을 전송할 때 수신 컨트랙트의 처리 기능을 호출한다.

이 과정에서 외부 컨트랙트 호출이 발생하므로 잔액과 같은 내부 상태를 안전하게 갱신하고 외부 호출 과정에서 재진입이 발생할 가능성을 고려해야 한다.

특히 ERC-1155를 기반으로 추가적인 기능을 직접 구현할 때에는 Checks-Effects-Interactions 패턴 등을 고려할 필요가 있다.

## 1. IDS와 IPS란?

### 1.1. IDS (Intrusion Detection System)

IDS는 침입 탐지 시스템으로 네트워크 트래픽이나 시스템 내부의 동작을 분석하여 비정상적인 행위와 보안 위협을 탐지하는 시스템이다.

공격으로 의심되는 행위를 발견하면 관련 정보를 기록하고 관리자에게 경고를 전달한다. 다만 공격을 직접 차단하지는 않는다.

### 1.2. IPS (Intrusion Prevention System)

IPS는 침입 방지 시스템으로 비정상적인 행위와 보안 위협을 탐지하고 공격을 실시간으로 차단하는 시스템이다.

IDS의 탐지 기능에 공격을 차단하는 기능이 추가된 형태라고 이해할 수 있다.

## 2. IDS와 IPS의 동작 원리

### 2.1. IDS의 동작 원리

네트워크 기반 IDS는 일반적으로 실제 통신 경로 외부에서 복제된 트래픽을 분석한다.

1. **수집**: 네트워크 트래픽을 복제하여 수집한다.
2. **분석**: 수집한 데이터를 탐지 규칙이나 정상적인 행위 기준과 비교한다.
3. **탐지**: 공격 패턴이나 비정상적인 행위를 식별한다.
4. **경고**: 탐지 결과를 기록하고 관리자에게 경고를 전달한다.

IDS는 실제 통신 경로에 직접 개입하지 않기 때문에 네트워크에 미치는 영향이 비교적 적다. 하지만 공격을 직접 차단하지 않으므로 별도의 대응이 필요하다.

### 2.2. IPS의 동작 원리

네트워크 기반 IPS는 일반적으로 실제 통신 경로에 직접 배치되는 인라인(Inline) 방식을 사용한다.

1. **수집**: 통신 경로를 지나는 네트워크 트래픽을 수집한다.
2. **분석**: 수집한 데이터를 분석하여 공격 여부를 판단한다.
3. **차단**: 정상적인 트래픽은 통과시키고 공격으로 판단된 트래픽은 차단한다.
4. **기록 및 경고**: 탐지 및 차단 결과를 기록하고 관리자에게 경고를 전달한다.

IPS는 공격 트래픽이 목적지에 도달하기 전에 차단할 수 있지만 정상적인 트래픽을 공격으로 잘못 판단하면 정상적인 통신에도 영향을 줄 수 있다.

## 3. IDS와 IPS의 유형

설치 위치와 분석 대상에 따라 네트워크 기반 방식과 호스트 기반 방식 등으로 구분할 수 있다.

| 유형 | 설명 |
| --- | --- |
| NIDS | 네트워크 트래픽을 분석하여 침입을 탐지 |
| HIDS | 개별 시스템의 로그, 파일 변경 등을 분석하여 침입을 탐지 |
| NIPS | 네트워크 트래픽을 분석하여 공격을 탐지하고 차단 |
| HIPS | 개별 시스템에서 발생하는 악성 행위를 탐지하고 차단 |

네트워크 기반 방식은 네트워크 전체에서 발생하는 통신을 중심으로 분석하고 호스트 기반 방식은 개별 컴퓨터나 서버 내부에서 발생하는 행위를 중심으로 분석한다.

이외에도 무선 네트워크 기반 침입 탐지, 방지 시스템과 네트워크 행위 분석 방식이 존재한다.

## 4. 침입 탐지 방식

### 4.1. 시그니처 기반 탐지 (Signature-based Detection)

미리 등록된 공격 패턴과 수집한 데이터를 비교하여 공격 여부를 판단하는 방식이다.

알려진 공격을 탐지하는 데 효과적이지만 등록되지 않은 새로운 공격은 탐지하기 어려울 수 있다.

따라서 새로운 공격에 대응하기 위해서는 탐지 규칙을 지속적으로 업데이트해야 한다.

### 4.2. 이상 행위 기반 탐지 (Anomaly-based Detection)

정상적인 시스템이나 네트워크의 동작을 기준으로 설정하고 해당 기준에서 벗어나는 행위를 탐지하는 방식이다.

예를 들어 평소보다 특정 서버에 대한 접속 요청이 급격하게 증가한다면 이를 이상 행위로 판단할 수 있다.

알려지지 않은 공격도 탐지할 가능성이 있지만 정상적인 행위를 공격으로 잘못 판단할 수 있다.

### 4.3. 상태 기반 프로토콜 분석 (Stateful Protocol Analysis)

프로토콜의 정상적인 동작 방식과 실제 통신 과정을 비교하여 비정상적인 행위를 탐지하는 방식이다.

프로토콜의 규칙을 위반하거나 현재 통신 상태에서 발생해서는 안 되는 요청 등을 탐지할 수 있다.

다만 프로토콜의 상태를 지속적으로 추적하고 분석해야 하므로 시스템 자원이 많이 사용될 수 있다.

## 5. IDS와 IPS의 활용 방법

### 5.1. IDS의 활용

- 네트워크에서 발생하는 비정상적인 트래픽 탐지
- 서버 내부의 비정상적인 파일 변경 탐지
- 반복적인 로그인 실패 및 비정상적인 접근 탐지
- 보안 사고 발생 시 로그를 활용한 원인 분석
- 보안 관리자를 위한 실시간 모니터링

### 5.2. IPS의 활용

- 악성 네트워크 패킷 차단
- 알려진 취약점을 이용하는 공격 차단
- 비정상적인 네트워크 연결 차단
- 악성코드 관련 통신 차단
- 중요 서버 및 내부 네트워크 보호

IDS와 IPS는 방화벽과 함께 사용되기도 한다.

방화벽이 설정된 접근 제어 정책을 중심으로 통신을 허용하거나 차단한다면 IDS와 IPS는 통신 내용과 행위 등을 추가적으로 분석하여 보안 위협을 탐지한다.

## 6. IDS와 IPS의 장단점

### 6.1. IDS

**장점**

- 네트워크 통신에 미치는 영향이 비교적 적음
- 공격 및 비정상적인 행위를 모니터링할 수 있음
- 수집된 로그를 보안 사고 분석에 활용할 수 있음

**단점**

- 공격을 직접 차단하지 못함
- 탐지 이후 별도의 대응이 필요함
- 오탐으로 인해 관리자의 업무 부담이 증가할 수 있음

### 6.2. IPS

**장점**

- 공격을 실시간으로 탐지하고 차단할 수 있음
- 공격이 시스템에 도달하기 전에 대응할 수 있음
- 자동화된 보안 대응이 가능함

**단점**

- 정상적인 트래픽을 공격으로 판단하여 차단할 수 있음
- 트래픽 분석 과정에서 네트워크 지연이 발생할 수 있음
- 인라인 장비에 장애가 발생하면 네트워크 통신에 영향을 줄 수 있음

## 7. IDS와 IPS의 차이점

| 구분 | IDS | IPS |
| --- | --- | --- |
| 목적 | 침입 탐지 | 침입 탐지 및 방지 |
| 공격 탐지 | 가능 | 가능 |
| 공격 차단 | 불가능 | 가능 |
| 관리자 경고 | 가능 | 가능 |
| 일반적인 네트워크 배치 | Out-of-band | Inline |
| 네트워크 성능 영향 | 비교적 적음 | 지연이 발생할 수 있음 |
| 오탐 발생 시 | 불필요한 경고 발생 | 정상적인 통신이 차단될 수 있음 |

IDS와 IPS의 가장 큰 차이점은 공격을 발견한 이후의 대응 방식이다.

IDS는 공격을 발견하여 관리자에게 알려주는 역할을 하고 IPS는 공격을 발견하는 것에서 그치지 않고 직접 차단하는 역할까지 수행한다.

## 8. 대표적인 IDS/IPS 도구

### 8.1. Snort

Snort는 오픈소스 네트워크 침입 탐지 및 방지 시스템이다.

설정된 탐지 규칙과 네트워크 패킷을 비교하여 악성 트래픽을 탐지하며 인라인 방식으로 설정하면 공격을 차단할 수도 있다.

- 실시간 네트워크 트래픽 분석
- 규칙 기반 공격 탐지
- 패킷 기록
- IDS 및 IPS 기능 지원

### 8.2. Suricata

Suricata는 오픈소스 네트워크 보안 분석 도구로 IDS, IPS 및 네트워크 보안 모니터링 기능을 지원한다.

다양한 네트워크 프로토콜을 분석할 수 있으며 멀티스레드 처리를 지원한다.

- 실시간 네트워크 트래픽 분석
- 다양한 프로토콜 분석
- 멀티스레드 처리 지원
- JSON 형식의 로그 기록 지원
- IDS 및 IPS 기능 지원

Snort와 Suricata 모두 네트워크 트래픽을 분석하여 공격을 탐지하고 차단할 수 있는 도구이며 사용 환경과 목적에 따라 선택할 수 있다.

## 9. 학습 소감

IDS와 IPS를 공부하면서 공격을 탐지하는 것과 실제로 차단하는 것에는 차이가 있다는 것을 알게 되었다.

처음에는 공격을 직접 차단할 수 있는 IPS가 IDS보다 무조건 효과적이라고 생각하였다. 하지만 IPS가 정상적인 트래픽을 공격으로 잘못 판단할 경우 서비스 이용에도 문제가 발생할 수 있다는 점을 알게 되었다.

따라서 하나의 시스템에만 의존하기보다는 네트워크 환경과 보안 목적에 따라 IDS와 IPS를 적절하게 활용하는 것이 중요하다고 생각한다.
